# TeamFinder
  3 Вариант

    Учебный проект на Django. Платформа для поиска единомышленников и совместной работы над pet-проектами. Реализован вариант 3: навыки проектов и фильтрация по ним.

# Возможности сайта

  регистрация и авторизация
  просмотр списка проектов и участников
  создание, редактирование и завершение проектов
  управление профилем и смена пароля
  отклик на проекты других пользователей
  добавление и удаление навыков проекта без перезагрузки
  фильтрация проектов по необходимым навыкам


# Использовалось

  Python 3.13
  Django 5.2.4
  PostgreSQL 16 (Docker Compose)
  Pillow — генерация аватаров
  python-decouple — загрузка переменных из .env


# Структура

  `users` — пользователи, авторизация, профили
  `projects` — проекты, участники, навыки
  `templates` — HTML-шаблоны
  `static` — CSS, JS, картинки
  `team_finder` — конфигурация и константы


# Как запустить проект


# 1. Виртуальное окружение
  python -m venv venv
  source venv/Scripts/activate

# 2. Зависимости
  pip install -r requirements.txt

# 3. Создать файл .env
  cp .env_example .env

  Сгенерировать DJANGO_SECRET_KEY:
  openssl rand -base64 32

  Скопировать .env_example в .env и заполнить:
    DJANGO_SECRET_KEY=<сгенерированный_ключ>
    DJANGO_DEBUG=True
    DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost

    POSTGRES_DB=teamfinder
    POSTGRES_USER=postgres
    POSTGRES_PASSWORD=postgres
    POSTGRES_HOST=localhost
    POSTGRES_PORT=5432

# 4. Запустить базу данных
  docker compose up -d

# 5. Тестовые данные
  python manage.py makemigrations users projects
  python manage.py migrate
  python manage.py seed_demo

    применит миграции
    создаст навыки (Python, Django, C++, C#, 1C, HTML, CSS, JavaScript, PostgreSQL и др.)
    создаст администратора
    создаст тестовых пользователей
    создаст 5 проектов с навыками и участниками

# 6. Запустить сервер
  python manage.py runserver

    Сайт доступен по адресу: http://127.0.0.1:8000


при каких либо неполадках в первую очередь стоит очистить кэш браузера

# Что было сделано

Изначально в репозитории был только стартовый каркас Django и готовые шаблоны со статикой.
Основная работа была в том, чтобы собрать полноценный backend под требования третьего варианта.

## Что было сделано

  В репозитории изначально находился чистый Django-проект с готовой вёрсткой.
  Вся серверная часть написана с нуля под задачи варианта 3.

  Выполненные работы:

    подключена кастомная модель User, вход через email
    созданы приложения users и projects
    описаны модели Skill и Project со связью многие-ко-многим
    подготовлены формы: регистрация, вход, профиль, смена пароля, проект
    настроена админ-панель с русским интерфейсом
    числовые и текстовые константы собраны в одном файле constants.py
    реализована пагинация списков проектов и пользователей
    написана команда seed_demo для автоматического наполнения базы
    настроен Docker Compose для PostgreSQL
    поправлены шаблоны и статика под вариант 3 (фильтры, навыки, стили)


# Почему пришлось менять шаблоны и стили

  В исходных файлах из `templates_var3` были проблемы, не связанные с заданием, но мешавшие работе:
  Что именно менялось:
  `skills.js` — в двух местах исправлено `skill.id` на `skill.skill_id`,
      так как сервер возвращает именно `skill_id`
  исправлен project_list.html — фильтрация теперь работает через skill.name|urlencode
  добавлены стили для пагинации
  исправлены стили карточек проектов (flex вместо 
      grid для равномерного распределения и чтобы карточки проекта не разъезжались)
  исправлены стили страницы проекта (перенос длинных слов, выпадающие подсказки навыков)
  исправлены стили фильтра (белый блок с рамкой, активный фильтр подсвечивается)
